# Аугментация шумом проприоцепции при k=1

Помогает ли наложение гауссова шума на состояние робота во время обучения
адаптации по одной демонстрации (one-demo adaptation)? Мотивировано работами по изменению проприоцепции
(«Adapt Your Body», 2025; AugInsert): при k=1 политика видит одну траекторию состояний манипулятора
и может привязать действия к проприоцепции с точностью до миллиметра.

12 независимых полных файнтюнингов (рецепт идентичен
`2026-08-22_18-10-40_pretrain_smolvla_full_ft_low_k`): задачи задания 0–2 ×
α ∈ {0.00, 0.01, 0.03, 0.05}, k=1 (только официальная demo_0). Во время обучения
`observation.state` возмущается **после** нормализатора MEAN_STD внутри
`policy.forward`: `s̃ = s + α·ε`, где `ε ~ N(0, I)`, что эквивалентно
σᵢ = α·Std(sᵢ) для каждого измерения в исходных единицах. Истинные (ground-truth) действия и изображения
не затрагиваются; при оценке шум не применяется. Шум поступает из выделенного
`torch.Generator` (seed 91000), поэтому основной поток RNG не изменяется, а
вариант α=0.00 в точности воссоздает рецепт full-FT k=1 (контроль внутри эксперимента;
ориентир full-FT: 2/20, 19/20, 14/20, среднее 0.583).

Реализация: обертка (wrapper) внутри процесса вокруг функции `train()` из lerobot, с пропатченной
`make_policy` для установки обертки forward; сам цикл обучения не модифицирован.
Оценка: только n_action_steps=50, 20 эпизодов,
батч 1, сиды окружения/шума установлены в `1000 + episode_index`, начальное состояние = индекс эпизода,
горизонт 300, все видео сохранены. Гейт: задача 0 / α=0.00 в прямом и обратном порядке
эпизодов должна дать точное совпадение.

Прогнозы заморожены в `reports/PRIOR_EXPECTATION.md` перед любым запуском. Крупные
чекпоинты сохраняются в `/var/tmp/vla_outputs/state_noise_k1_20260822_224355`.

Эксперимент с одним сидом обучения (seed 1000); только для k=1.
